## Why this fork remains public

GitHub requires forks of public repositories to remain in the public fork
network. The visibility of this fork cannot be changed independently.

The fork is kept as a transparent, reproducible evaluation surface:

- the upstream source and attribution remain intact, and the `upstream-drift`
  workflow checks that claim rather than asserting it — it reports any
  upstream-owned file this fork has modified, and how many commits behind
  upstream the snapshot is;
- the included workflow is configured to run the upstream test suite on Python 3.10–3.13;
- the wheel gate checks packaging and required skill assets;
- lint and type checks run in report-only mode, so their findings are visible
  without this fork gating code it does not own;
- the verification record is regenerated by a script, not written by hand;
- local portfolio work is not mixed into this repository.

## What the evaluated snapshot contains

Agent Reach is a Python CLI and library that gives an AI agent read and search
access across a set of internet platforms. It is an installer, doctor and
config tool rather than a wrapper: once installed, agents call the upstream
platform tools directly. Multi-backend routing is the core design — each
platform has a preferred backend and fallbacks, for example:

```
bilibili.py     → bili-cli ▸ OpenCLI ▸ search API
xiaohongshu.py  → OpenCLI ▸ xiaohongshu-mcp ▸ xhs-cli
```

Two operational details matter when reproducing the verification below, because
they change what a run can actually reach:

- **Twitter/X** reads require `TWITTER_AUTH_TOKEN` and `TWITTER_CT0` to be set
  explicitly in the process environment. Cookies saved by `agent-reach
  configure` only let `agent-reach doctor` report whether configuration is
  complete; they are not injected into upstream commands.
- **Credentials are never committed.** Every channel that needs auth reads it
  from the environment or from `~/.agent-reach/`, outside the repository.

Upstream's documentation is authoritative for everything else; see the links
at the end of this file.

## Verification

```bash
git clone https://github.com/MiMindMendinc/Agent-Reach.git
cd Agent-Reach
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -c constraints.txt -e ".[dev]"
env -u GITHUB_TOKEN -u GH_TOKEN pytest -q
```

`GITHUB_TOKEN` is cleared because `Config` reads it from the environment, and
one test asserts that no optional feature is configured. On a shell that exports
it, that test fails for reasons unrelated to this repository.

To re-derive the whole verification record — upstream integrity, staleness, a
clean-venv test run — in one step:

```bash
bash scripts/fork-audit.sh
```

The latest audit is recorded in [FORK_AUDIT.md](FORK_AUDIT.md).

## Boundaries

- This is not a Michigan MindMend product.
- No upstream capability is presented as original portfolio work.
- Credentials, cookies, tokens, and private configuration must never be
  committed.
- Live third-party platform behavior can change independently of this fork.
- This fork owns exactly six paths: `README.md`, `FORK_AUDIT.md`,
  `CONTRIBUTING.md`, `SECURITY.md`, `.github/`, and `scripts/fork-audit.sh`.
  `CONTRIBUTING.md` and `SECURITY.md` carry only a routing banner above
  upstream's text, which is kept verbatim. No upstream code is modified, and
  the `upstream-drift` workflow reports any change to it.
- Bugs, features, support, and security reports belong
  [upstream](https://github.com/Panniantong/Agent-Reach/issues), not here.
